# Fish Media 路由器（v0.5.2）

按**交付物**派发。先问自己：用户最终要拿走的是什么？

## 当前能力边界（诚实版）

**本 Skill 集当前包含四个配方页：`product-photo-series`（商品商业图系列，已验证）、`thumbnail-cover`（封面图，已毕业）、`narration`（旁白，v0.1）、`ugc-product-video`（商品带货视频，v0.2 Fish 全链实测）。**（休眠：subtitles-burn=本地通用能力；explainer-video=纯 MCP 达不到成片线——两者为平台需求证据）

| 用户要拿走的交付物 | 派发 | 边界 |
|---|---|---|
| 一组/一张商品商业图 | `fish-media:product-photo-series` | 仅商品/产品图；人像写真、风景、纯插画不在范围，如实告知 |
| 视频/内容的封面图、缩略图 | `fish-media:thumbnail-cover` | 无人像封面已支持；出镜人物封面需人脸参考（未验证，首次如实披露）；只评分析不生图 |
| 把文字念成旁白/配音音频 | `fish-media:narration` | 无时长约束旁白；视频限时旁白未启用；听审=用户验收 |
| 视频广告 / 旁白 / 配音本地化 / 声音视觉化 | **诚实拒绝**：告知"该配方页尚未包含，不在已验证范围内"，建议直接使用 fish-prod MCP 原生工具并说明可提供估算/流程建议，但不冒充有已验证流程 | — |
| 不确定 / 混合请求 | 按"最终拿走的产物"访谈澄清（≤3 问，带选项） | — |
| 平台排障（卡单/对账/退款） | 如实告知暂无专门配方页，按通用排障流程查询原任务 | 不重提生成 |

## 负向边界（五件套）

1. **联合条件**：媒体生成意图 + 明确交付物形态，同时成立才派发
2. **反过度触发**："你们能生成视频吗"= 问答，不派发不执行
3. **改道指引**：本机文件操作 → 普通 Bash；未覆盖交付物 → 诚实拒绝（见上）
4. **兄弟去重**：派发后不再调用其他配方页；一次会话一个主交付物
5. **例外枚举**：用户说"先别生成，只要方案" → 只产出计划，不调用生成

## 全局门禁（引用骨架，不改写）

确认门禁按 `skills/shared/core-skeleton.md` 的**唯一表述**执行（交互=用户确认；预授权任务=任务描述即确认；都不满足=不提交）。访谈上限统一 **3 问**。此处不另行表述。

## 开发者接入类请求（不走本路由）

用户是**开发者**，要写代码调用 Fish Audio API（接入、TTS/ASR/音色/声音设计的代码样例、401/402/429 排障）时，不属于媒体交付，**不要拒绝也不要走上面的配方页**，直接使用 `fish-api-*` 系列：`fish-api-setup`（key/余额/限流/计费）→ `fish-api-tts` / `fish-api-asr` / `fish-api-voices` / `fish-api-voice-design`。判别：用户要的是"成品音频/图/视频"→ 本路由；要的是"怎么用代码做到"→ fish-api-*。
