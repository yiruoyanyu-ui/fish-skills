# 旁白（Narration）· v0.1

对标：Higgsfield narrator（250 行，时长约束型）——其"时长窗口+实测重试"概念与"音色锁"纪律已蒸馏；其边界声明"普通 TTS 不归 narrator 管"同样吸收：**本页只做无时长约束的旁白**，视频限时旁白待未来页。

## 执行前必读

骨架见 `../shared/core-skeleton.md`（唯一表述）。旁白页特有：**文本保真是旁白的"硬约束"**——不增删改用户原文（平台朗读扩展如数字转读仅限格式不改义，且须披露）；**音色锁纪律**——音色 id 记入任务记录，每次调用前重读，不凭记忆传参。

## 流程（骨架的旁白实例化）

1. **缺行检查**：文本（必有，缺失→中止）；音色（未给→`search_voices` 列候选让用户选一次；无人值守→**锁定默认音色并披露**，默认=工作区已验证音色）；语言从文本推断；多段按段拆分。
2. **朗读格式扩展（可选）**：数字/日期/符号先做朗读格式转换（`studio_enhance_text` 或手动），披露"仅格式转换未改义"。
3. **生成**：`text_to_speech`（voice_id+text）→ 拿音频 URL。
4. **QC（按宿主能力分级）**：元数据级必做（音频 URL 可达、格式、时长若返回、扣费）；**听审=用户**（自然度/停顿/语气 AI 无法替代，交付中明确请求听审反馈）。
5. **交付**：音频 URL + 音色 id 与名称 + 语言 + 扣费 + 披露清单（音色谁定的/扩展了什么/听审请求）。
6. **重生成**：用户不满意→改文本或换音色重跑；生成失败→查原 ID 不重提。
